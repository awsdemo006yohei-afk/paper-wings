Paper Wings — delivery

nightbuild 2026-09-28 · one-button paper-plane flyer · build & host & ads

What shipped

  • Done — full 3D endless flyer: hold to rise, release to dive, pointer steers. Pooled obstacles (paper boxes, spinning blades, golden rings), recycled scenery, chase camera.
  • Done — daily sky: palette + wind + world seeded from the date. Everyone flies the same sky that day; a new one tomorrow.
  • Done — scoring: meters + rings (+50) + near-misses (+10), ranks from Gust Guest to Wing Poet, personal best in localStorage.
  • Done — silent by design (user call): no audio, no audio assets.
  • Done — shareable 1200×630 canvas score card via Web Share (download fallback).
  • Done — 14/14 offline tests on the pure logic module (node tests/logic.test.mjs).
  • Done — keyless: vendored three.js r170, no build step, no API keys, runs from any static host.

Hosting

  • Done — dedicated GitHub repo, game at repo root, GitHub Pages enabled (URL in chat).

Ad revenue — wired and pending Google's review

  • Done — AdSense live: publisher ca-pub-9657119821733951 in the page head, responsive banner on the start panel, fresh rectangle unit every game-over (the natural break), privacy.html included, and ads.txt served both at the site path and the domain root (via the user-site repo, as the IAB spec requires).
  • Waiting on Google — site review after the code was detected; usually a few days to ~2 weeks. Ads render unfilled (invisible) until approval; revenue starts then.
  • Reality check: at $1–5 RPM, meaningful money needs thousands of daily plays — the share card is the growth lever. Expect pocket change first, not rent.

Honest gaps

  • No leaderboard (localStorage best only) — a backend would compromise the keyless/static story.
  • Interstitial slot reserved but empty until AdSense approval; games policy also wants a natural break, which game-over provides.
  • Desktop + mobile pointer input tested in headless Chromium; real-device touch feel not verified.
